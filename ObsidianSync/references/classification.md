# 分类 / 标签 / 链接规则（obsidiansync）

`@save` / `@import` / `@link` 执行时按本文件判定。原则：**先复用，后新增；宁入 Inbox，不误归档。**

## 1. PARA 目录判定

按以下顺序逐条判断，命中即止：

| 目录 | 判定条件 | 典型例子 |
|------|----------|----------|
| `10_Projects` | 有明确目标 + 截止时间 + 可交付成果 | "下周要交的方案"、有 deadline 的任务 |
| `20_Areas` | 长期持续关注、需长期维护、无截止 | 某项专业技能、长期研究方向、健康 |
| `30_Resources` | 未来可能用到的通用参考资料，非项目专属 | 收藏的文章、工具、书籍笔记、论文 |
| `00_Inbox` | 无法确定 / 碎片想法 / 快速捕捉 | 一句话灵感、待消化的链接、临时笔记 |
| `40_Archives` | 已完成或已搁置（一般不在 save 时直接归档，由 @maintain 迁移） | 完成的项目、放弃的方向 |

**判定顺序**：先问「有时间限制吗？」→ 有则 Project；无则问「是长期责任吗？」→ 是则 Area；再问「是外部参考资料吗？」→ 是则 Resource；都否 → Inbox。
**不确定时一律落 `00_Inbox`**，由后续 @maintain 提醒处理，绝不强行猜测归入 10–40。

## 2. 笔记类型 → 模板

| 类型 | 用 80_Templates/ | 触发特征 |
|------|------------------|----------|
| 概念 | `概念笔记模板.md` | 解释一个定义 / 原理 / 知识点 |
| 项目 | `项目笔记模板.md` | 有目标、里程碑、进展记录 |
| 资源 | `资源笔记模板.md` | 外部内容（文章/书/工具/视频/论文） |
| 日常 | `日常记录模板.md` | 日志、灵感、每日复盘 |

类型与 PARA 目录多数情况下对应（概念→Area/Resource，项目→Project，资源→Resource，日常→Inbox/Area），但二者独立判断：目录管「放哪」，类型管「用哪个模板」。

## 3. 标签规则

1. **先查现有**：`rg "^tags:" KB_ROOT` 取库内已有标签集合；新标签若与已有标签语义相同（含中英文 / 缩写）则复用，避免 `机器学习`/`ML`/`machine-learning` 并存。
2. **命名**：中文或英文小写连字符；不带空格、不带 `#`（frontmatter `tags` 是数组，正文 `#标签` 才带 `#`）。
3. **每篇 ≤5 个**，必含两类：
   - 类型标签：`概念` / `项目` / `资源` / `日志`
   - 主题标签：从内容关键词提取（领域、技术、对象）
   - 可选状态标签：`待完善` / `进行中` / `已归档`
4. 不造一次性标签（如 `#tmp`、`#杂`）；这类内容落 Inbox 且不加主题标签。

## 4. 链接检测算法

输入：新笔记正文 + 标题候选。步骤：

1. 取候选锚点集 = 库内所有 `.md` 的文件名（去扩展名）∪ 各笔记 frontmatter `aliases`。
2. 在正文中查找锚点的出现（精确匹配优先；中文按子串，英文按词边界不区分大小写）。
3. 对每个命中产出 `[[锚点]]`，并记录出现位置（第几段），供 `@link` 精确插入。
4. 去重：同一锚点只建议一次；若正文已含 `[[锚点]]` 则跳过。
5. 上限建议 5 条，按「锚点在正文出现次数」排序；其余列入「可选链接」供用户勾选。

> 反向链接：无需手动维护。在 A 写 `[[B]]`，Obsidian 自动在 B 的「反向链接」面板显示 A。只有当用户希望 B 显式列出关联时，才在 B 的 `## 🔗 关联` 段补 `[[A]]`。

## 5. 文件名 / 写入规范

- 文件名：描述性、简短、无 `/ \ : * ? " < > |`；避免纯日期（日常记录除外）。
- 日常记录：`YYYY-MM-DD.md` 或 `YYYY-MM-DD-主题.md`。
- frontmatter 必填：`title` `tags` `created` `updated`；`updated` 每次编辑都刷新为当天。
- 正文使用模板既定结构（📝 摘要 / 📖 正文 / 🔗 关联 / 📚 参考资料 / 🏷️ 标签），缺段留空标题即可，勿删结构标题。
